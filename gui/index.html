🎨 色彩設計の理由（Semantic Color Architecture）
Near-Black Surface Hierarchy (#08090a → #111214 → #1d1e20)
理由: 装飾的なドロップシャドウを排し、明度差と 1px ボーダーのみでレイヤー階層（背景・カード・入力欄）を精密に分離するため。
Amber / Orange (#f59e0b) — 要入力・注意喚起 (Needs Input / Queued)
理由: ユーザーの視線を「まだ入力が完了していない必須項目（① アプリ名・URL）」や「待機中キュー」へ迷わず誘導するため。
Emerald Green (#10b981) — 検証完了・正常稼働 (Validated / Runtime Ready)
理由: 入力値の検証通過（①〜③の準備完了）、ビルド成功、および Chromium / 署名ツールチェーンの健全性を即座に保証するため。
Indigo Blue (#5e6ad2) — プライマリ実行アクション (Action Ready / Primary CTA)
理由: 前提ステップ（①〜③）がすべて緑（Ready）になった瞬間にのみ ④ と作成ボタンを Indigo に点灯させ、「今すぐ実行できる操作」を一意に示すため。
Isolation Purple (#a855f7) — セッション分離・Google OAuth 保護
理由: 通常のステータス色（緑/橙/青）と混同させず、アプリ固有のサンドボックス領域（persist:bundleId）と認証保護機能を識別するため。
Crimson Red (#ef4444) — エラー・破壊的操作 (Failure / Trash)
理由: ビルド失敗やアプリ削除（Trash）など、即時対処や注意を要する不可逆・異常状態のみに限定使用するため。
